# Ferrugo website

The Ardo 6 site for Ferrugo, served by GitHub Pages at
[sebastian-software.github.io/ferrugo](https://sebastian-software.github.io/ferrugo/).
There is no custom domain, so the site is built for the base path `/ferrugo/`
(`ardo.config.ts`). Router links and Markdown links get the base from Ardo;
plain links in the homepage go through `withBase()` in
`app/components/home-data.ts`.

Every page wears the Monografie header and footer from
`ferramenta-family/monografie` (`monografie.css`); the homepage reads on the
Monografie page, and the documentation keeps the Ferra reading layout from
`ferramenta-family/ferra` (`ferra.css`, `ferra-ardo.css`). Shared visual changes
belong in the family package. The site styles only its homepage specimens and
shell seams, in CSS files beside their components under `app/components/`,
every selector scoped to an `fg-` class; the build checks that.

From this directory:

```sh
pnpm install --frozen-lockfile
pnpm dev
pnpm verify
pnpm preview
```

`pnpm verify` checks the homepage samples, lint, formatting, types, the
production build, internal links and assets under the base path, and every page
at eight viewport widths with accessibility and interaction checks. It needs
the repository's Rust toolchain and Playwright Chromium
(`pnpm exec playwright install chromium`).

`scripts/site-pages.mjs` lists the documents the site publishes.
`scripts/write-site-data.mjs` generates ignored Markdown routes from them,
rewrites relative repository links, and derives the release and minimum Rust
version. Edit the original documents in `docs/`, not their generated routes. The
handwritten introduction lives at `content/getting-started.md`.

Everything the homepage shows about Ferrugo's behavior is generated by
`scripts/render-home-samples.mjs`; nobody edits it by hand:

- `app/data/previews/*.png` and `app/data/home-samples.json` are real output of
  `samples/`, a small program that depends on the published `ferrugo-thumbnail`
  and `ferrugo-native` crates from crates.io at the exact version pinned in
  `samples/Cargo.toml` (its own Cargo workspace, outside the repository's). It
  renders committed fixtures from `fixtures/`; the JSON records the crate
  version and each input's SHA-256. After a release reaches crates.io, raise
  both pins and run `pnpm sample:write`.
- The homepage shows no speed comparison. The repository's
  [performance claims policy](../docs/policies/performance-claims.md) sets the
  conditions for one, and no recorded run compares several renderers under
  them yet.

`pnpm sample:check` renders again and fails when the JSON no longer matches or
when a committed preview differs from the new render by more than the
repository's visual-diff thresholds.

`.github/workflows/homepage.yml` checks pull requests and deploys `main` to
GitHub Pages.
